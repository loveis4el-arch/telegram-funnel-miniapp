# Мини-воронка регистраций: Telegram-бот + дашборд в миниаппе

Бот ведёт человека по воронке: `/start` → приветствие → «Поделиться телефоном» → два сообщения по расписанию (через 10 с и через 1 мин);
во втором — кнопка «📋 Получить чек-лист» (нажатие — отдельный шаг воронки). Дальше «эфир через 10 минут» и «мы начали»:
в `config.yaml` — по времени эфира (`webinar_at` + `before_webinar`: за 10 минут и в момент начала),
в `config.demo.yaml` (видео) — сразу после кнопки (`after: click:<key>`), чтобы не ждать эфира.

> В Telegram Web клавиатура бота свёрнута под значок ⌘ справа в поле ввода; в приложении на телефоне кнопка видна сразу.
Дашборд — Telegram Mini App: сколько людей дошло до каждого шага, конверсия, очередь, последние события.

**Стек:** aiogram 3 · FastAPI · PostgreSQL 16 · Docker Compose. Тексты и тайминги — `config.yaml`.

```
 Telegram ──► bot (aiogram) ──► PostgreSQL ◄── api (FastAPI) ◄── миниапп (dashboard.html)
                   │                ▲
                   └─ планировщик ──┘  раз в 1 с: «у кого наступило время» → отправить → отметить
```

## Запуск (3 команды)

```bash
cp .env.example .env          # вписать BOT_TOKEN от @BotFather
docker compose up -d --build  # db + bot + api
docker compose logs -f bot    # видно каждый шаг воронки
```

Дашборд в браузере: http://localhost:8000 (при `DASHBOARD_ALLOW_BROWSER=1`).
PostgreSQL наружу не открыт: сервисы ходят к нему внутри сети compose, порт 5432 на компьютере не занимается.

Без Docker: `python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt`, своя PostgreSQL в `DATABASE_URL`, затем `python -m app.bot` и `uvicorn app.api:app`.

### Миниапп внутри Telegram (нужен https)

Telegram открывает Mini App только по https. Для локального запуска — бесплатный тоннель:

```bash
cloudflared tunnel --url http://localhost:8000   # выдаст https://….trycloudflare.com
```

Адрес — в `.env` как `WEBAPP_URL`, ваш Telegram id — в `ADMIN_IDS`, `DASHBOARD_ALLOW_BROWSER=0`, затем `docker compose up -d bot api`.
Бот сам ставит кнопку «📊 Дашборд» в меню чата; ещё есть команда `/stats`.

### Быстрое демо (для видео)

`FUNNEL_CONFIG=config.demo.yaml docker compose up -d` — та же воронка, второе сообщение через 20 с вместо минуты.

## Поменять воронку без кода

`config.yaml`: тексты, кнопка, время эфира `webinar_at` (с часовым поясом), шаги расписания: `key`, `text` и одно из трёх —
`delay` (секунды от телефона), `after: click:<key>` + `delay` (от нажатия кнопки), `before_webinar` (секунды до эфира).
По желанию `button` + `on_click`. Опоздавшему (зарегистрировался в 17:55) «эфир через 10 минут» не уходит — уже прошло.
⚠ `webinar_at` в репозитории — 5 ноября 2026, 18:00 МСК: если смотрите позже, поставьте время в будущем, иначе сообщения 3–4 не придут (так и задумано). Шагов может быть сколько угодно.
После правки: `docker compose restart bot api`. Конфиг проверяется при старте (повтор `key`, отрицательный `delay` — ошибка с понятным текстом).

## Как устроено и почему

| Решение | Зачем |
|---|---|
| Очередь сообщений в PostgreSQL, а не `asyncio.sleep` в памяти | перезапуск или падение бота не теряет запланированные сообщения: после старта он досылает всё, у чего наступило время |
| `UNIQUE (tg_id, step_key)` и регистрация «один раз» | повторный `/start` или второй контакт не ставят сообщения второй раз |
| Чужой контакт не засчитывается | `contact.user_id` должен совпадать с отправителем |
| Заблокировал бота / чата нет → `failed`, без повторов | очередь не забивается вечными повторами; на дашборде видно «не доставлено» |
| Подпись `initData` проверяется на сервере | цифры видит только тот, кто открыл дашборд из Telegram (и из `ADMIN_IDS`, если задан) |
| Тесты на отдельной базе `funnel_test` | тесты чистят таблицы — рабочую базу не трогают |

Таблицы: `users` (кто, телефон, когда пришёл и зарегистрировался), `scheduled_messages` (что, кому, когда отправить, когда отправлено, ошибка), `events` (лента для дашборда).

## Тесты

```bash
docker compose --profile test run --rm tests   # 22 теста, из них 8 — на настоящем PostgreSQL
```

Проверяют: конфиг (10 с и 60 с, порядок, повтор ключа), подпись миниаппа (верная, подменённая, чужой токен, устаревшая),
расчёт конверсии (и деление на ноль), воронку целиком на базе (сообщение +10 с уходит, +60 с ещё нет, без дублей; потом уходит второе),
недоставленное сообщение не висит в очереди, кнопка телефона видна всегда, сообщения не обещают ответа, который бот не разбирает.
